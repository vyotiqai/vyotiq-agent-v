Agent V 1.1.0 widens where the agent can run and tightens what it may do without asking. It adds Amazon Bedrock, Google Vertex AI and Azure OpenAI, hooks that can check or stop a tool call and a proxy setting; asks before a risky command, before a repository's own git programs run and before a folder opens from a link; keeps API keys out of task records; and can delete all of your data. The task list, the record and the inspector are reworked around what you do next, and a task that changed code must show a real check passed before it calls itself done.

## Added

- **The agent checks its own work before it stops.** In Agent mode, a turn that changed code with no passing test, typecheck or lint since the last edit gets one more turn, asking the agent to run a check or say plainly what it left unverified. It asks once each time the task runs, on a send or a resume, and helper instances are held to it too.
- **A risky-command guard.** A terminal or test-run command that deletes outside the workspace, or the workspace itself or its .git folder, force-pushes, hard-resets, runs git clean with force, formats a disk or pipes a download into a shell now always asks: with approvals off, in unattended mode, and even for a command you allowed before. The card says what the command does and offers only Allow once or Deny, and nothing is remembered. If nobody answers in 15 minutes the command is denied, and with no window open it does not run.
- **A spend limit per task.** Settings, Agent, Runs: a limit in whole dollars, off at 0. The task and its helper instances count towards it. When spend reaches the limit the task asks under Needs you, Allow another or Stop here, and a stop shows as Stopped, not Failed. The limit is checked before each model call, so one call can run past it, and a model with no known price counts as nothing.
- **Amazon Bedrock.** Settings, Providers: choose an AWS region and sign in with a Bedrock API key or with AWS access keys. Claude models think the way they do elsewhere, and the model list shows the inference profiles and text models your account offers. The keys are kept with your other provider keys, in the operating system's secure storage.
- **Google Vertex AI.** Settings, Providers: name a Google Cloud project and a location, then sign in with a service-account key file or with the gcloud login already on the computer, which is read when a call is made and never copied. Gemini and Claude models are offered; models from other publishers are refused with a message that says so.
- **Azure OpenAI.** Add an endpoint of kind Azure OpenAI and paste the https address of your resource or deployment. You pick models by deployment name, and the key goes in the api-key header.
- **Extra headers, and a proxy.** A custom endpoint takes extra headers, one per line, up to sixteen; headers that would break the request are refused. Settings, General, Network sets a proxy: System uses HTTPS_PROXY and NO_PROXY, then the operating system's setting; Manual takes an address and a bypass list; None connects directly. It applies at once to the app's own traffic, the updater and the browser, and to the commands the agent runs in the terminal. Localhost always connects directly.
- **Hooks.** A hooks file can run a command before a tool call, after one, when the agent stops and when it needs you. Exit code 2 from a before-hook blocks the call and tells the agent why; from an after-hook it adds your message to the tool result; from a stop hook it keeps the agent going, up to three times each time the task runs. Put the file in your data folder as hooks.json, or in a workspace as .vyotiq/hooks.json, which runs only after you allow that exact file and asks again whenever it changes. A hook cannot change a tool's input or output.
- **Helper and Utility models.** Settings, Agent: the helper model runs helper instances, and the utility model writes compaction summaries and commit messages. Both default to the task's own model, and only providers with a key are listed.
- **Find references and symbols.** The agent's language-server tool can now list where a symbol is used, the symbols in a file and the symbols matching a name across the workspace, for the TypeScript, Python, Rust, Go and C and C++ servers it finds in your project or on your PATH. Results past one hundred are counted, not listed.
- **Folder rules where they apply.** When the agent reads or edits a file, the AGENTS.md, CLAUDE.md and .cursorrules files in the folders above it, and the Cursor and Vyotiq rule files whose globs match it, join the result. Each is read once per run, at most six per result, and none can override the agent's own constraints or tool policy.
- **MCP servers can ask you a question.** When a server needs input mid-call, a form card appears in the calling task: text, number, yes or no, single or multiple choice, up to eight fields. A bad answer asks again, and Skip declines. A server that adds or removes tools is picked up without reconnecting.
- **The agent can read a PDF.** It gets the text, page by page and under a page header, in the same windows as any file. A scanned PDF reports that it has no text to read, since nothing recognises images, and files over 64 MB are refused.
- **Task rows say more, and take an answer.** A running task shows its current step, a waiting one shows what it asks, a terminal command appears as the command with Allow once and Deny on the row, and a task in review shows how many lines changed and how many checks are met. A task's helper instances fold under it, its hover card gains a plan meter, and its menu adds Retry for a failure that can be retried and Fork.
- **Settling a task can be taken back.** Keep all, Undo all and Commit each show a toast with Undo, and Undo all no longer asks first. A commit can be taken back, leaving its changes staged, while it is still the latest on its branch, has one parent and is on no remote branch. A kept file can be un-kept while the run is stopped. The result reads Committed, Kept, not committed or Undone, with Kept or Undone against each file.
- **Ask about an element on a page.** In the Browser tab, Pick an element to ask about shows Chromium's inspect overlay; click, or step with the arrow keys and press Enter. Each pick becomes a chip in the instruction line, and the agent is given the page address, the element's name, role and selector, where it sits and up to 240 characters of its text. A pick ends when the page navigates, and elements inside frames cannot be picked.
- **Approvals and answers sit where they were asked.** An approval or question appears inside the step that raised it, the record says You answered or Allowed by you, always for this task once a gated call has run, and a run notes Allowed by a rule once. Output lines that pass or fail are tinted, a folded stretch of steps reads like 6 lookups, 2 commands, 3 files edited, and helpers started together share one block. A Copy the summary button joins the result.
- **The result lists the files a run changed.** Each file shows New, Deleted or its added and removed lines and opens in Changes, past eight files a line says how many more are there, and Kept and Undone marks follow the settling.
- **Open checks lead Review.** In Changes and in Review for a task that has stopped, the done-when checks that were not met, or never checked, come first, each with a button that asks the agent to cover or check it. Met checks fold to a count.
- **A plan bar.** A thin rule on the task header has one segment per step of the plan: done, running, needing you, failed.
- **Number keys answer questions.** With an option focused, 1 to 9 pick it, and a question with one single-choice field is answered by the digit.
- **New files read as new files.** A file the task created shows one number column and a plus gutter, with no old side to compare.
- **Alt Up and Alt Down open the previous and next task** in the order the list shows.
- **Search your tasks.** The magnifier in the navigator filters titles at once and, after a pause, searches the text of your messages, the agent's and its tool output in the open workspaces, archived tasks included. Each task gives one hit, newest first, with the matching line.
- **Archive or delete several tasks at once.** Ctrl or Command click toggles a row, Shift click takes a range, and Space with Ctrl, Command or Shift selects the focused one; a bar offers Archive, with a toast to undo it, and Delete, which asks once. Running tasks and tasks waiting on you are left out, and the View menu adds Archive all done.
- **Rebind the shortcuts.** Settings, Shortcuts: Change, then press the keys. A chord already in use, or one that is reserved for copy, paste and the like, is refused with the reason, and every row has a way back to its default.
- **Export, import and reset your settings.** Settings, About, Settings file. Export leaves out keys, sign-ins, MCP servers, endpoint headers and pinned and archived tasks. Import shows each change before you confirm it, never brings in base addresses, the proxy or approval settings, and only adds endpoints. Reset all keeps your provider and model, endpoints, MCP servers, rules and pinned tasks.
- **Delete all my data.** Settings, Storage, Retention. It measures first and lists what goes: tasks and undo points, worktree folders, Home files, and your keys, sign-ins, settings, extensions and logs. One confirmation, and the app restarts clean, as on a first run. Your projects, your branches and commits, and anything at your providers stay; keys are removed from this computer, not revoked.
- **New task is one brief.** The brief, an always-ready Done when line (Enter adds a check; up to twenty), and the control row sit in one box, and Ctrl Enter starts it. Where it works, This folder or New worktree, sits at the header's edge. Settings, Agent adds New tasks start in a worktree, off by default.
- **Extensions can be switched on and off in the list.** Installed servers, skills, plugins and your own rules have a switch on the row, and a hover menu to turn one off here or in every workspace. A Google server that uses your own client secret gains Reset Google sign-in.
- **Settings is one column** with an index that follows where you are. Effort sits under Model, and the effort levels now say what they cost. Settings, Agent, Memory has Clear for a workspace's notes.
- **A folder can be mentioned.** Pick a folder in the @ menu and the agent is given its listing, up to 40 entries with sub-folders marked, and told when the list was cut short. The @ menu lists files as soon as you type @, and a picture in your workspace attaches as an image.
- **Type in the page.** The Browser tab has a button that moves the keyboard into the page, for a login or a form, when the agent is not driving it.
- **File links in the record open the file.** A path such as src/a.ts or src/a.ts:42 in the agent's notes opens Files at that line, and a heading link scrolls inside its own note.
- **Shift Tab in an empty message box switches between Ask and Agent.**
- **Usage shows what you kept.** A Kept share beside the totals, and one chart by day, Spend, Tokens or Tasks.
- **Screen readers hear how a run ended.** Failures and needing you are announced at once, finished runs politely, once per inbox item, following your Notifications settings.

## Improved

- **Only a real check counts as one.** A command used to count as verification if it exited cleanly, whatever it was; in recorded runs, 143 of 1,679 such commands were actually tests, typechecks or lints. Now only those count, whether the agent ran them as a test or in the terminal. A test run that failed counts as a failure, a lint that exits on a warning counts as a failure, and a check whose output was cut off proves nothing. A command chained with others never counts.
- **A check goes stale when anything changes the files after it.** Writes from the terminal, from an MCP tool, from applying a patch or from a merge now all count, not only the agent's own edits. Editing the task's plan or its done-when list does not.
- **The plan panel says why a task is unverified:** the last check failed, no check ran after the files changed, or files changed after the last check passed.
- **Diagnostics works on more projects, and reads more tools.** A root tsconfig that only lists project references used to check zero files and report clean; it is now built as a whole. Output from Rust and Cargo, Python, mypy and ESLint is read, a check that timed out on Windows left its processes running and hung the step, and now stops them all.
- **Changes made by applying a patch show up in Changes and can be undone,** like any other edit. A helper instance limited to some folders can no longer patch files outside them, and can now run diagnostics, which it was refused 22 times in recorded runs.
- **An edit card shows the real line numbers** of a replacement in the file, not a count starting at 1. A whole-file write shows none.
- **The @ and / menus fit the composer.** They follow its width, put a header over the list, and say when a search failed instead of showing an empty list that looks like no matches. The path tree beside the @ list is gone.
- **When the agent waits on a helper instance, the answer says whether that helper checked its work.**
- **Models that write a tool call as text now have it run,** for the tools the step offered, and the text is hidden from the record.
- **Claude through OpenRouter now uses prompt caching,** and Gemini thinking carries across tool calls on the direct API as well.
- **MCP calls get more room while the server is working.** The two-minute idle limit restarts whenever the server reports progress, a call is capped at ten minutes of work, and both pause while a form waits for you.
- **Home opens faster.**
- **Run approvals follow the unattended setting.** In unattended mode, asking to run a command that is not a check as a test, or running a script, now asks first, the same as the terminal.
- **One Set up.** The What needs your OK? dialog that appeared on your first send is gone. Set up asks once, on first run or if you started tasks without ever choosing, holds an instruction you sent until you choose, and has Edits and commands preselected.
- **Day spend in Usage counts bills plus estimates,** marked est., so a figure can differ from 1.0.0.
- **A narrow window keeps a rail.** Under 1,024 pixels a thin rail shows a glyph for each task that needs you, is running or is in review, with Home, Inbox, Extensions, Usage and Settings. The inbox groups its items as Needs you, Ready for review and Earlier.
- **The same look across dialogs, radios and popovers,** with one bar on every dialog, and the context meter says Record where it said Messages.
- **The app says task and instruction** where it said chat and prompt, and a Markdown export is headed Instruction.

## Removed

- **Thirty-nine skills are gone from Extensions.** The twenty-six vendored from Matt Pocock's Skills for Real Engineers, and thirteen of our own: implement-feature, fix-bug, review-code, write-tests, explain-code, create-skill, goal, frontend-design, accessibility, api-design, persona-builder, refactor and analyze-api. A skill you already installed stays installed and keeps working; it just no longer receives updates. To write a new skill, the /create-skill command is still there.
- **The harness review and apply commands.** They drafted and applied changes to the agent's own system prompt from past runs, and only worked inside the Agent V repository itself. Run ratings are kept.
- **The Density setting.** The 1.0.0 notes listed it as removed, but that build still showed it. It only sized controls the redesign no longer draws.
- **Previous and Next file in Changes,** which now scrolls as one column, and the confirmation before Undo all, which the toast replaces.

## Fixed

- **Undo no longer loses its history when its index file is damaged.** The index is rebuilt from the saved checkpoints and the damaged copy kept aside; before, every earlier undo point silently disappeared.
- **Undo after a crash no longer overwrites a file it cannot prove is untouched.** If the app stopped mid-turn, a file changed since the agent's write is left alone.
- **A rewind that leaves a change of yours no longer marks that turn as fully undone.**
- **When one tool in a batch fails, the results of the others are kept.** They are saved with the step, where before they were thrown away.
- **A run can no longer loop forever.** A run stops after 500 steps with a notice, counted each time you send or resume, and a model that repeats the same tool call in one reply is cut off the way a flood of calls already was; one run spent 33 minutes that way.
- **A run with an odd receipt no longer drops out of Home and Usage.** A receipt with one malformed count used to fail as a whole; now only that field is set aside.
- **A run's receipt lists every file it wrote,** across every time it was resumed, not only the last.
- **The line counts in Changes match the list** for large rewrites, and a removed line that starts with two dashes is no longer dropped from an edit card.
- **Waiting on a helper instance after a restart** no longer polls its status twice a second, and no longer leaks memory while it waits.
- **A damaged settings file is set aside, not overwritten.** It is renamed with the time, the defaults load and the inbox says so; before, the next save replaced it with defaults. A settings file that cannot be read stops saves instead of writing over it.
- **A crash no longer drops the run's last writes.** The app saves queued messages, events and status, for up to three seconds, before it exits; it used to wait a quarter of a second.
- **Quitting from Home, Settings, Extensions or Usage no longer waits and then asks** whether you want to quit with run data still saving.
- **Helper instances use the task's model** when no helper model is set, not the workspace's default.
- **A tool the agent wrote for itself asks even with approvals off.** The approval gate was skipped when approvals and MCP protection were both off.
- **The diagnostics check no longer fails on pnpm projects** because pnpm passed an extra flag on to the linter.

## Security

- **A repository's own git programs no longer run unasked.** Settings in a repository's git config can name programs that run on a plain status, diff or merge: a file-system monitor, clean and smudge filters, external diff and merge drivers. The app's git now skips them, Changes lists what it skipped, and Allow for this repo, once confirmed, runs them for exactly that set; a change to the set blocks them again.
- **Opening a folder from a link asks first.** A vyotiq link to a folder that is not open and not among your twenty most recent now shows its path and asks before opening it.
- **Keys stay out of task records.** Text shaped like an API key, a token, a private key or a Bearer or Basic credential is replaced with a marker in a task's messages, events and brief before it is written, and the agent is told never to write one. It recognises the formats of the common providers, so a key in an unusual format can still get through, and tasks recorded by earlier builds keep what they hold.
- **Agent-written tools run without the app's own environment variables.**
- **The packaged app refuses a debugger switch and a changed app archive.** It ignores the inspect switches, and on Windows and macOS refuses an app archive whose contents changed.
- **A helper limited to some folders is held tighter.** It cannot apply a binary or headerless patch or write into the agent definitions folder, and the vyotiq link handler now checks the data it is given.
- **undici is updated past GHSA-rfgv-xxqx-mfg5** in the build tooling; it never ships in the app.

## Known issues

- Windows and macOS builds are unsigned. Windows SmartScreen warns on first run, and macOS Gatekeeper refuses a double-click — open it from the right-click menu once.
- Crash reports are not sent from this build. Crashes are recorded on your own machine only.
- Amazon Bedrock and Google Vertex AI were built from the providers' documentation and tested against stand-ins, not live accounts. Bedrock, Vertex AI and Azure OpenAI show tokens but no cost, so a spend limit cannot count them.
- Allowing a command from a task's row or the inbox does not show the warning the task's own card shows for a risky command. Open the task to see why it is asking.
- The risky-command guard reads the command as written and knows a fixed list. It does not flag git branch -D, git checkout . or git stash drop, or a delete hidden in a script or a python -c line.
- A hooks file that names an event the app does not have is ignored as a whole, and the reason is only logged. Matchers use the app's own tool names, such as terminal and edit.
- The models Vertex AI lists are the same for every project.
