Teammates stop being something only you can set up. The agent can now create them, tune them, hand them work and read back what they produced, and a teammate's memory is finally something you can open and edit rather than infer. Alongside that: a project file can no longer quietly grant a teammate more freedom than you gave it, twenty-six new skills arrive in Marketplace, and a rebuild no longer takes the running window down with it.

## Added

- **The agent can run the team itself.** It can list who exists, create a teammate, retune one, delete one, hand it a brief on a schedule, and read back what that work produced — the same roster, the same files, the same queue you see in the pane. A teammate the agent makes is indistinguishable from one you made yourself and shows up with no reload. These are Agent mode only; Ask and Plan cannot reach them.
- **Delegated work reports back.** Handing a task to a teammate used to be a one-way door: the roster filtered out everything that had finished, so a run could give work away and never learn a thing about it, not even that it had failed. Recently finished work is now named in the roster, and a run can read a finished task's closing message and the files it wrote. It can only read work done in the project it is working in — a teammate is global and its work is not.
- **A teammate can be created with something already in its head.** A new teammate can be given starting notes, written into its memory for the open project. It is the only way anything can put notes in another teammate's memory, and it happens at creation, on a memory that did not exist a moment earlier.
- **You can read, edit and clear what a teammate remembers.** Teammates → a teammate → Memory shows the notes it carries in the open project: what is injected into every step, what it keeps between runs, and the notes those point at — with a warning when notes exist on disk that nothing references, because those are invisible to the teammate. This is the only thing in the app that deletes a teammate's memory. Deleting the teammate still does not.
- **A project cannot hand a teammate more freedom than you gave it.** A per-workspace tuning file travels with the repository, so cloning one used to be enough to change whether a teammate asks before running tools, whether it resumes work on launch, and where its runs execute. Those three now do nothing until you press Review and accept on that specific file — everything else in it still applies. Acceptance is recorded against the file's exact contents, so editing it or pulling a change to it asks again.
- **Twenty-six new skills in Marketplace.** Matt Pocock's Skills for Real Engineers, vendored under his name and MIT licence: test-driven development, diagnosing bugs, domain modeling, resolving merge conflicts, writing specs and tickets, reviewing changes, and more. Several are written to call each other, so installing one installs the siblings it needs and tells you which ones it added — a skill whose first instruction is to load a skill you do not have is inert.
- **A skill for making teammates.** Marketplace carries the playbook for the tools above: when a teammate is worth having at all rather than a one-off helper or just doing the work yourself, how to write a role with a boundary instead of an adjective, what to give it as starting notes, and which choices cannot be taken back — a deleted teammate retires its name for good.
- **Empty workspaces offer to start a repository.** When the project you have open is not under version control, the strip beneath the new-chat heading says so and offers to run git init on a click. Nothing runs it for you — not on open, not on the agent's behalf — and it refuses if the folder is already inside a repository somewhere above it.
- **The agent can write itself a tool.** When a run keeps repeating the same mechanical shape that no built-in tool covers, it can write one as a small module, which joins its catalog on the next step and stays available to later runs. It may use only what Node itself provides. Calling one asks you first, every single time the file behind it has changed — the approval card shows the code, and it is the only place anyone reads that code before it runs.
- **Teammates are told their own name.** A teammate can refer to itself, sign its work, and be addressed by name. Its persona is now given as its role rather than as its identity, which is what it always was — a teammate was previously being told that its name was a sentence describing its job.
- **Finished-run notifications say who finished.** A delegated run sets no goal of its own, so the only field the old title had to work with was empty for exactly the runs you had walked away from.
- **Compaction and commit-message spend is counted.** Both are billed calls with no turn behind them, so neither appeared in your activity. They are now recorded against the run and the day they happened on, broken down by which of them it was, and folded into your totals — including a compaction that failed partway, which is the spend most worth seeing.

## Improved

- **The Teammates pane is one rail and one panel, not a single long scroll.** The queue, five groups of settings and a danger zone shared one scrollport, with a Save bar fixed to the bottom of it that painted over the last row of whatever sat underneath. The teammate's identity now stays put while you work, its activity and its settings are separate panels, and the Save bar sits below the scroll rather than on top of it. A teammate with a queue opens on its work; a new one opens where there is something to do.
- **The page header sits with the content it titles.** It used to be pinned to the window edge while the body was centred in a narrower column, so on a wide display the title and what it titled were three hundred pixels apart.
- **Retry says why it cannot run.** A finished task belonging to a project you have closed cannot be re-queued, so Retry is now shown disabled and naming that project, rather than absent or present-and-failing.
- **The Changes panel stops going blank on the repositories with the most to say.** A workspace carrying a large untracked tree — a vendored toolchain, a build of a language runtime, a virtual machine image — produced more status output than could be read in one go, and that came back indistinguishable from a clean tree. It now says it is showing a truncated list instead of claiming there is nothing there. The same panel also stopped reading tens of thousands of files it was about to discard, which is what made it hang on those workspaces.
- **A freshly started repository shows its branch.** The command used to ask could not answer before the first commit, so a repository you had just created looked like it had no branch at all.
- **A rename in your working tree no longer invents a file that does not exist.** Git reports a rename as two paths, and the second was being read as a change in its own right, so a renamed file produced a phantom entry beside it.
- **The strip above a new chat keeps up.** What the agent knows about the workspace — its branch, its rules, whether the code index is ready — was read once when the chat opened and then went stale. It now updates as those things actually change.
- **Post-compaction notices are said once.** A notice that a fold had just happened was kept and re-sent on every remaining request of the run, so the model was still being told to get on with the work it had already done dozens of steps later.
- **Compaction is checked against what the model actually wrote.** The check ran after missing facts had been spliced back in, so it could only ever report perfect coverage and the retry it guards was effectively unreachable. It now scores the summary itself and reports a real number.
- **A conversation the provider has lost no longer ends the run.** Some providers hold prior turns server-side and are sent only the new part; when that stored turn expires or is evicted, the request fails in a way that reads like a permanently malformed request. The full history is still here, so the step resends it in full and carries on — once per step, so a server that keeps refusing cannot loop.
- **A skill that will not load says which thing is wrong.** "Unknown or disabled" was wrong in both directions: a skill sitting in Marketplace uninstalled was reported as disabled, sending you to a switch that does not exist yet, and a plain typo looked like a settings problem.
- **A half-finished model pin is ignored, as the control already said it would be.** Choosing a provider before choosing a model produced a pin the save refused outright, so the whole form failed rather than the incomplete pin being skipped.
- **Chrome that draws across the top band of the window can be clicked.** A surface drawing its own header up there was covered by the window's own drag region, which swallows clicks before the page ever sees them. The bar now steps aside when something else has claimed that strip, and still leaves a handle to drag the window by.

## Fixed

- **The badge that means a run needs you never drew.** The asset and the state that selects it were named differently, so the app asked for an image that does not exist and the single most urgent badge silently cleared itself instead.
- **A build replacing the app under a running window no longer leaves it broken.** Three separate failures here: superseded parts of the interface were deleted while a window was still using them, the automatic recovery reload was allowed to happen only once per session so the second rebuild landed on a crash screen, and a window that was mid-load when it happened stayed blank with nothing left running to retry. Old parts are now kept until nothing can still be running them, recovery is rate-limited rather than spent, and a failed load is re-issued by the app itself.
- **A rebuild is no longer reported as a crash.** Recovering from one was being logged at crash severity, which put it into crash history and sent it onward as a renderer crash. It also now says what is happening — a short notice that a new build replaced this one — instead of the error screen.
- **Undo could delete files the agent never touched.** When a workspace holds more files than a single scan will record, the before and after scans can stop at different points, and a file that merely crossed that frontier was read as one the agent had created — which Undo then deletes. Classification now falls back to evidence that does not depend on how far the scan got.
- **A write that failed could still be listed as a change, and offered for undo.** What a file holds has to be recorded before the write that would replace it, so a write that then failed — against a path that was not there at all — left an entry behind for a file that never existed. It reached the Changes panel saying the run had written it, and because undo deletes what such an entry names, anything that later occupied that path would have gone with it. Entries the turn proves changed nothing are now dropped, and only what is actually on disk decides.
- **A file the agent really did create could go unreported.** A workspace holding exactly as many files as a single scan will record was read as one the scan had given up partway through, and a scan believed incomplete has its new files held back rather than risk inventing them. Only a scan that actually left directories unvisited is treated that way now.
- **Handing work to a helper run could fail several times over for the same reason.** The brief is a few separate fields, and a run that put the whole of it into the first one had its request refused by a check that named the missing field but nothing about what to do — so it sent the identical request again. What is missing is now filled in from what was sent, and the refusal says what the fields are.
- **Turning on a per-workspace tuning field for the model would switch itself back off.** Whether a field was overridden was inferred from its value, and a teammate with no model pinned globally seeded that field with no value at all — which read back as "not overridden". Every other field happened to seed to something and hid it.
- **Saving a tuning file with every field switched off wrote an empty file into your repository** instead of removing the file, because a field that had been switched off still counted as present.
- **A refused save of a tuning file looked like it had worked.** The reason was recorded and nothing showed it, so the form reported success and the file on disk never changed.
- **A skill package that depends on others is repaired at startup.** Packages installed before the catalog recorded those links are simply broken — they instruct the agent to load something that was never copied in. Missing pieces of bundled content are now restored on launch, the same way drifted bundled text already was.

## Security

- **A run cannot read another teammate's memory.** Reads resolved any path inside the workspace with no exclusions, and teammate memory lives inside the workspace under a directory named from the teammate's own display name — so a guessed path reached another teammate's private notes. Every read path is now checked against the namespace the run actually owns, and an ordinary chat, which owns none, is refused all of them.
- **Applying a patch is approval-gated like any other write.** A teammate set to act without asking still has to ask before editing, deleting, running a command or committing — but applying a unified diff, which writes arbitrary files into your tree, was missing from that list. It was the one way to make the same edits with no prompt at all.
- **A tool the agent wrote for itself has to be approved, and approving it does not carry over to a rewrite.** Such a tool is arbitrary code produced minutes earlier, so it stays gated even with approvals switched off, and writing it is itself gated — the approval card is the only place anyone reads that code before it exists. Allowing one is recorded against the exact contents approved, so a later rewrite of the same tool asks again.

- **Your file paths and the contents of your files no longer reach the log.** Scrubbing covered absolute paths only, so a path written relative to your project went to disk as it stood. The messages that quote your files back were worse — the nearest line to an edit that missed, the context a patch expected to find — and those were written out whole. They exist to tell the model what to try next, not to be kept, so a search that found nothing or an edit that missed now records only what kind of failure it was.

## Known issues

- **Existing per-workspace tuning files stop applying their autonomy settings until you accept them.** If you hand-wrote a file that sets whether a teammate asks before running tools, whether it resumes on launch, or where its runs execute, those three stop taking effect on first launch after this update, until you open that teammate and press Review and accept. Everything else in the file keeps working. This is deliberate and not grandfathered: the whole point is that a file nobody consciously read cannot grant itself freedom, and an install cannot tell your own file apart from one that arrived with a clone.
- **An agent run can create a teammate that never asks before running tools, and hand it work.** This was chosen over the safer default, in favour of leaving the control with you. What still holds regardless is the gate above: editing, deleting, running commands, committing, applying patches, and calling connected servers stay approval-gated for every teammate, however autonomous it is set to be — unless you have allowlisted that tool for the project yourself.
- **Nothing limits how many teammates a run may create.** A confused run can fill the roster. Deleted teammates retire their names permanently, so the names it burns do not come back.
- **Windows and macOS builds are unsigned.** Windows SmartScreen warns on first run, and macOS Gatekeeper refuses a double-click — open it from the right-click menu once to get past that.
