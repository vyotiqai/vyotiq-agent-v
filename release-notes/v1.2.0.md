Agent V 1.2.0 is the release where the app can hold the agent to rules you wrote, and where the surfaces around a task grow into real work surfaces. Permission rules can allow, ask or deny a tool, a command or a path, and an operating-system sandbox can confine the commands the agent runs; the file editor, the task's git bar and the pull request tab gain find and replace, hunk undo, fetch and pull, and inline review threads; a task can repeat itself on a schedule and can be exported and brought back as a file. Underneath, storage settings stop holding on to work they should have let go of, and the log, the terminal and the browser keep less of your data than before.

## Added

- **Permission rules that allow, ask or deny.** Settings, Agent: write a rule against a tool, the first words of a terminal command, or a path given from the workspace root, absolutely, or from your home folder. They answer before Ask before and Always allowed get a say, deny beats ask and ask beats allow, and the field says which rules reach the prompt. A workspace can ship its own deny and ask rules in its permissions file; its allow rules are ignored. The app's data folder and that file itself are denied whatever you write, and the files that usually hold a secret — an environment file, your SSH keys, your personal skills — ask, unless one of your own allow rules covers them.
- **A sandbox for the commands the agent runs.** Settings, Tools, Sandbox: Workspace only lets the agent's terminal, its test runs and its diagnostics read the disk but write only the workspace, that workspace's git folder with its hooks and config excepted, the temp folders, and the package caches that already exist; Network then cuts it off the internet. It uses the operating system's own sandbox on macOS and Linux, it is off by default, and it never covers the terminal you type into. Every confined command says in the record which confinement it ran under, and a command that failed because it was refused gets a one-line reason so the agent stops retrying it.
- **Find and replace across the workspace.** The Files search row gains Match case, Whole word and Regular expression, with the query still read as a regular expression as it always was, and a second row that replaces every match in the workspace once you confirm how many matches in how many files. A file with unsaved edits in an open tab is left alone and named, as is one that is binary or too large to read back, and a search that stopped early says so instead of pretending it was complete.
- **Undo one hunk instead of the whole file.** Every block of a modified file in Changes carries its own undo: that change is taken back out of the file as it is now and nothing else in it moves, with a toast that puts it back while nothing has changed where it was. A file the task created or deleted is still undone whole.
- **Fetch, pull and push from the task's git bar.** A muted count each way sits beside the branch, and a menu beside them fetches, pulls, pushes, or publishes a branch that has no upstream yet; a new branch is named in an inline field beside it. A branch that has diverged asks whether to merge or rebase and says what each does to your commits. Pull and New branch wait while a task is working in that checkout.
- **Review threads on a pull request, inside the app.** The Pull request tab lists the inline review comments by file, with the line each sits on, whether it is resolved or outdated, and how many replies it has; reply to one, resolve or unresolve it, or hand one comment — or every unresolved comment — to the task as an instruction. Resolved threads fold behind a count, and a thread's line opens the file there.
- **Check out an open pull request.** When the branch has no pull request of its own, the tab lists the repository's recent open ones and checks one out here, refused while a task is working in that checkout or while your tracked files have changes.
- **A task can repeat.** Repeat… on a task's menu gives it a schedule — daily, weekly on chosen days, every so many minutes, or a cron expression — and Scheduled tasks collects them all, across every workspace, with what each runs, when it next runs, and how its last run went. On or off, Run now, Edit and Delete sit on the row, and the last run opens like any task. Schedules run while the app is open, and a time missed while it was closed runs once when it opens. Each run is a new task, marked with a repeat glyph in the navigator and marked again when it is catching up a missed time.
- **Helper types you write once.** A markdown file defines a helper: a name, one line saying when to use it, the tools it may use, and the model it runs on. Put it in a workspace's agent-types folder, in its Claude agents folder read as it is, or in your data folder for every workspace; the first file to claim a name wins. The tool list narrows what the helper's mode already allows and never widens it, a named model falls back to the helper model when it cannot run here, and the type's name shows on the instance row in the task and the navigator.
- **Fallback models.** Settings, Providers: up to three models, in order, that a step moves to when the provider is down — a server error, an overloaded model, a refused or reset connection, a DNS failure, a timeout. Usage and rate limits keep waiting on the task's own model rather than switching, a bad key is still reported to you, the task's own model is tried again ten minutes into a long turn, and the next turn starts on it anyway.
- **Export a task as a file, and bring one back.** Export as JSON writes the whole task — the brief, the record, the checks and the pictures the tools stored — with anything shaped like a key replaced; Import task… reads one into a workspace as a finished, read-only task with a new identity, which you fork to carry on from. A task too large to write, a file that is not a task, and one from a newer build are each refused in words you can act on.
- **Usage says where the money went.** The range is 7, 30 or 90 days or two dates you pick, a long range labels its bars by date instead of every day, and a breakdown gives each workspace its share of the spend or the tokens with its tasks under it, costliest first, each row opening the task. Export CSV writes one row per task per day, with cells that cannot be read as formulas when the file is opened in a spreadsheet.
- **The keyboard list and the documentation are in the app.** `?`, or Ctrl or Command with `/`, opens every shortcut grouped by what it acts on, showing the keys you rebound rather than the defaults. The command palette gains Keyboard shortcuts, Open documentation, Inbox, Scheduled tasks, Import task… and Show or hide reasoning.
- **A diagnostics bundle to send with a bug report.** Settings, Diagnostics exports the logs, the crash history, memory figures and your settings as one zip, with keys, tokens, environment and header values taken out and your home folder and username replaced. Nothing is sent from there; you attach it yourself.
- **Run a task with no window.** Vyotiq can run one task from a script or a build with your saved settings, keys, rules, skills and servers, and answers its approval prompts by policy: deny everything, allow only reads, browsing and file edits, or allow all. The result comes back as the answer alone, one JSON object, or a stream of them as things happen, with exit codes that say whether the run finished, ran out of steps or spend, was refused, timed out, or was interrupted.

## Improved

- **The file editor is an editor.** Files highlights 39 languages instead of ten, finds and replaces inside the open file, offers your language server's completions as you type, and keeps several cursors at once. Its find panel and completion list wear the app's own controls instead of the library's, and a file nothing can write — one you are only reading — keeps find and drops editing.
- **Hooks follow Claude Code more closely.** Two events are new: one when a task starts and one when you send an instruction, and either can stop what follows, with the reason handed back. A hook's JSON output is read where Claude Code reads it — a decision to block, a permission denied, extra context — and a file naming an event or a shape this app does not have now keeps its other hooks and logs what was skipped, instead of being ignored whole.
- **The record reads as one column.** The brief, the steps and the instruction line share one measure and one edge, so the composer's box lands on the record's card instead of inside it, and the goal banner above it stacks at the same width. Inline code loses its grey tile for a hairline under the text, headings take one vertical rhythm with a rule under a section name, tables drop their vertical lines so the rows read as rows, a wrapped heading balances itself, and a paragraph no longer ends on one short word.
- **Stop sits where you send.** The task header's row is gone: Stop, the task's menu and the pane's own buttons sit at the top of the record and hold their corner on a long task, and the plan bar moved to the Plan panel, where the steps it counts are the ones listed below it. A task that has started but has streamed nothing yet says what it is doing instead of showing an empty column.
- **The commit box says where its words came from.** It is a real field you can edit freely, it says whether the message is still the agent's draft, typing your own no longer waits behind that draft, and once nothing is waiting on review a line says how the edits were settled — committed to which branch, undone, kept, or some kept and some undone — with a way through to the pull request.
- **Commit and create a pull request keeps the task's work.** The button commits as a plain commit does, marks the task's files as taken, and writes the pull request the way the Pull request tab drafts it: the task's title, its result, and its done-when checks.
- **An undone file can come back.** Bring back puts the agent's version of a file on disk again and puts it back on review, offered while the run is stopped and nothing else has changed the file since.
- **A task you stopped can be picked up again.** Resume is on a stopped task's menu alongside Retry, and Archive is now offered on a running task with the reason it cannot be used yet, instead of being absent.
- **A pasted link names the task it points at.** A task whose instruction is nothing but a link is titled by its target — the site and its path — instead of eighty characters of percent-encoded query string, so a deep link pasted into the composer still reads as something.
- **Background shells are bounded, and quieter.** At most twenty-four background terminal sessions run at once across the whole app, where the limit counted per turn and one task could hold more than a hundred; a command over the limit says so and explains what to wait for. Their output now reaches the Terminal panel in one message per frame rather than one per read from the shell, so a chatty command no longer asks the panel to redraw hundreds of times a second, and a stream that ends flushes what it owed.
- **A listed server is no longer a running server.** Servers that talk over standard input keep one warm session per workspace that is doing work, rather than one per folder you have ever opened; a server in a workspace you come back to connects on its first tool call. Closing the last workspace now releases the processes it was holding, and Refresh or Retry still warms everything.
- **Storage settings do what they say.** Delete old tasks now deletes a task once it is past the kept count or past the age limit — either one is enough — where both had to be true at once, so the setting read "keep 30" but meant "keep everything for 60 days". The size cap frees space by dropping a workspace's code index, which is rebuilt on demand, when undo points alone cannot cover the overage; before, most of the managed disk had no eviction path behind it at all. Storage left behind by a workspace nobody has opened for longer than the grace period is now collected, not only the folders holding no run records, and never for a workspace with a task running in it.
- **Helper branches stop piling up.** The branches a helper instance leaves behind are pruned by a count as well as by age and reachability, so a backlog of recent branches that carry their own commits — and so fail both older rules — can no longer grow without limit.
- **The log keeps what support needs.** Rotations are numbered and five generations are kept; before, a second rotation overwrote the only archive, and yesterday-and-before was unrecoverable. A support bundle and the crash panel both read every generation, so a crash is still reported after its own log file has rolled over, and a log line cut by the length cap says how much was cut.
- **A recovered blip is no longer logged as a failure.** One dropped frame inside an open stream — a reset connection or an upstream error partway through an answer — is a warning now, with the retry still doing its work, and a plan limit worded like throttling waits on the task's own model instead of being retried as if the server were busy.

## Removed

- **The task header row.** The 40px bar above a task, carrying its title, state, branch, added folders and plan bar, is gone. Its controls sit at the top of the record instead, the plan bar moved to the Plan panel, and the title, the branch and the added folders are read where they are needed rather than repeated above everything.

## Fixed

- **Closing a terminal tab no longer quits the app on Windows.** The packaged build refuses a helper the terminal library started for that, and the refusal ended the whole app when you closed a tab.
- **A task no longer keeps a stale inbox row.** Resuming, retrying or continuing a task withdraws the Finished or Failed notice its last stop published, so the inbox cannot describe a run that is going again. A pending question still outlives its run's stop.
- **Sending is refused while an attachment failed.** The send button used to offer to fix a bad image, file or recording and then send anyway; it now refuses until the attachment is resolved or removed.
- **Attachments and dictation no longer collide.** The attach control closes while a recording is being taken, and the mic greys out while the composer cannot take input, rather than looking live and doing nothing.
- **A send from a split lands in the pane you typed in.** With two tasks side by side, the shortcut that focuses the composer used to land in the left pane's instead.
- **Revealing a search result no longer takes the keyboard.** Finding a file in the tree and waiting for its folders to load stole focus from the editor you had already clicked into; focus moves only when the tree holds it or nothing does.
- **A put-back hunk says so when it cannot be.** Restoring an undone hunk finds it where it was left, or at the nearest place it still matches; a file that changed under it is left as it is rather than patched roughly.
- **A headless run that wrote nothing is a failure.** A run whose whole output is its transcript now fails when neither of its files holds a row, instead of reporting success with nothing behind it for a caller to read.
- **A server a workspace needs stays reachable.** A server configured for a workspace that was deliberately left cold connects the first time a tool call, resource or prompt reaches for it, rather than answering that it is not connected.
- **Settings says which rules are in force.** The Rules row names the instruction and rule files that will reach the prompt for the open workspace, or says plainly that the generic list is standing in while that is read.

## Security

- **A repository's own git programs are covered further out.** Fetch, push and signed commits reach much further than a status or a diff, and the guard now covers what a repository can set for them: the SSH command, the git proxy, credential helpers, the askpass program, a remote's upload and receive programs, the signing program, the alternate-refs command, a hooks path that leads out of the repository, and a remote address that is a shell command. Your own global settings are put back where a repository overrode one, a plain program name with no path or arguments still counts as installed software, and the repository's own hooks inside it still run, as git runs them.
- **A web page the agent opened cannot reach your network.** A public page in the agent's browser can no longer fetch your router, a dev server on localhost or a cloud metadata address by riding the tab's allowance; only a page that is already local may reach local addresses, and a public page redirected back into your network is cancelled. The agent is told what was refused and how to open a local page itself.
- **The packaged app refuses to run as Node and ignores injected startup options.** Two Electron safeguards left on because turning them off broke something are now off, with their causes fixed first: the terminal's process listing no longer needs a forked helper, and the certificate store a proxying TLS setup depends on no longer needs the environment to pass it through. The refusal to start under a debugger, and the check that the app archive has not changed, are unchanged.
- **Output the agent fetched is marked as untrusted.** A curl, wget or GitHub API result in the terminal is wrapped in the same envelope a browsed page gets, so instructions inside a server's response read as data rather than as orders. A build, a test run or a directory listing is left exactly as it was.
- **Deleting all your data reaches the copies.** The pass removes whole top-level entries, which is what takes a backup folder holding its own copy of your keys and settings with it, and it does so by position rather than by name.
- **A helper confined to some folders is not offered tools it cannot use.** Instead of spending a turn on a refusal, a helper capped to a shared tree is offered only the tools that stay inside it, is told why, and keeps the check and test runners it needs to verify its own work.

## Known issues

- Windows has no sandbox. Confining one process's writes and its network there needs native calls this app has no dependency for, so the control is disabled with that reason rather than pretending to confine anything.
- While the sandbox is on, a tool the agent wrote for itself is refused with an explanation instead of running unconfined behind a setting that says commands are confined: it runs in a process the app starts, which cannot be wrapped.
- A package cache that does not exist yet is not writable inside the sandbox, so a first install into a new cache fails there; run that one install outside it.
- The sandbox confines files and network, not everything: on macOS a confined command can still talk to system services, and on both systems it can read every file you can except the app's data folder and your SSH folder.
- Headless runs refuse rather than answer: a command held for a person — the risky-command guard, or a permission rule that says ask — is refused, and no headless run ever writes an "always allow" or "allow for this task".
- Starting the app while a headless run is going, with that run's workspace open in it, marks the run interrupted.
- Headless on Windows: from an interactive prompt use the launcher in a checkout, or start the program and wait for it, because a windowed program there does not report its exit code. Writing the result to a file always works.
- The private-network rule refuses a flow that leaves a local page for a public one and is redirected back — an OAuth callback to localhost, for instance. Ask the agent to open the callback address itself.
- Permission rules and the risky-command guard read a command as written and know a fixed list of programs: a delete hidden inside a script or an inline interpreter line is not flagged.
- Putting an undone hunk back only works while nothing has changed where it was, and only until the app quits.
- Windows and macOS builds are unsigned. Windows SmartScreen warns on first run, and macOS Gatekeeper refuses a double-click — open it from the right-click menu once.
