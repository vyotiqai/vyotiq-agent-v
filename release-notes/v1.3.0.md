Agent V 1.3.0 is the release where delegation stops being automatic. The agent used to hand every request to sub-agent instances and to publish a plan before it started; it now decides both, and a single small edit, a direct answer or a read-only lookup stays in the main task instead of spawning anything.

## Improved

- **Handing work to another agent is now a judgment call.** The agent starts a sub-agent when your request splits into two or more independent pieces that can run in parallel, or when one piece is large enough that an agent given a narrow brief would finish it faster. A single small, tightly coupled edit, a straight answer and a read-only lookup are done in the main task, because doing them there is quicker and clearer, and nothing is spawned just to look thorough.
- **Steps that depend on each other stay together.** When the agent does hand work over, it never splits steps that need one another, and each delegated step still goes to its own agent with a complete brief — what it is to deliver, what is in scope, how it will be checked and which parts of your workspace it touches — so a child never guesses at the conversation you cannot see.
- **A plan is published only when the work touches your workspace.** Work that changes files, runs commands or otherwise acts on your project gets a plan, with each step carrying a check you can watch run. A direct answer or a read-only lookup gets none, and a plan is never published as a token of thoroughness.
- **A plan's steps are no longer forced into separate agents.** Where the agent delegates, each delegated step maps to an agent of its own; a run that stays in the main task maps no steps to agents at all. The plan you see in the record and in the Plan panel now describes the work, not an org chart.
- **Fewer wasted turns on ordinary work.** Asking a run that had not published a plan where the plan was cost two extra model round trips on a normal request — measured as four provider calls where two were expected — so that question is gone. A run that did publish a plan is still told when the plan reads as shallow, and a run whose checks are all met is not sent back to decorate a plan it already finished.
- **The documentation describes the conditional behaviour.** The page on instances now says an agent starts a sub-agent when the work splits into pieces worth running in parallel or when one piece is big enough to give an agent of its own, and that a small edit or a direct answer stays in the main task; the worked example on building a feature on a branch says a plan is written for a task of that size rather than for every task.
