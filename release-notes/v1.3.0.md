Agent V 1.3.0 is the release where the app keeps working when you look away, and where the work around a task stops sending you to a terminal or to GitHub. Tasks keep running in the tray when the window closes, approvals say what an edit will change and can be answered with a note, spend has a daily and a monthly budget, and the agent reads the web without driving a browser. The Changes and Pull request tabs cover checks, issues, reviewers, auto-merge, hunks and branches. Delegation is now a judgment call. Windows gets a sandbox for the agent's commands, and Windows and Linux get Arm builds.

## Added

- **Keep running in the tray.** Settings, General: with Keep running in the tray on, closing the window leaves your tasks, loops and schedules running. Quitting while a task is live names the tasks first. The tray menu lists running tasks, marks the ones waiting on you, and offers New task and Stop all tasks.
- **Schedules from the start.** New task has Schedule…, which runs the brief on a schedule, a new task each time. Home shows the runs Coming up, and Repeat… is on the task's own menu as well as the navigator's.
- **Approvals show the change.** An edit's approval card shows the change as −/+ rows with a count, and a whole-file write is compared with the file on disk. The card also offers Always allow edits under the edit's top folder (`src/`, say), saved as permission rules, beside allowing the tool everywhere.
- **Answer an approval with words.** Deny with a note tells the agent why and what to do instead. A command can be edited, then run once in place of the agent's. How long a request waits before it is denied is a setting, and 0 means it waits for you.
- **Budgets across tasks.** Settings, Agent: a daily and a monthly budget in US dollars, counted over every workspace, closed ones too. You get a notice at 80% and another past 100%. Running tasks are never stopped, but with Hold new work at the budget on, new tasks, follow-ups, schedules and loops wait once a budget is spent. Usage shows a Budget line with today and this month against each budget.
- **Prices for every model.** Models the built-in table doesn't know are priced from models.dev, and you can set your own input, output and cached-input prices for any model or endpoint. Commit-message drafts and other side calls show in Usage instead of only in the log.
- **The agent reads the web without the browser.** `web_fetch` reads a page as text, and PDFs too, paging through long ones with an offset. `web_search` asks DuckDuckGo, Brave, Tavily or SearXNG, chosen in Settings, Tools. Neither drives the agent's browser, so neither trips a CAPTCHA.
- **More for the agent.** `browser_console` reads the page's errors and failed requests. `memory_delete` and a memory browser let the agent and you remove a single note. `github_pr_checks` reads a pull request's checks, and `github_issue` can open one issue. MCP servers can ask the model for a completion (sampling) and send you to a URL (URL elicitation).
- **Open Agent V from anywhere.** `Vyotiq.exe C:\code\api`, or `.` for the folder you are in, opens that folder as a workspace. On Windows, Explorer's right-click menu has Open in Agent V, and Settings, General, Command line can put a `vyotiq` command on your PATH: `vyotiq .` opens a folder and `vyotiq --prompt "…"` runs a task with no window. On macOS, drop a folder on the Dock icon. Other tools can link to `vyotiq://open?ws=…` to open a folder, or `vyotiq://new?ws=…&brief=…` to open New task with the brief filled in, never sent. A link to a folder you have never opened asks first.
- **Files other agents use, read as they are.** Skills from `.claude/skills`, `.agents/skills` and `~/.claude/skills`; commands from `.claude/commands`, `.github/prompts/*.prompt.md`, `~/.vyotiq/commands` and `~/.claude/commands`, with `$ARGUMENTS`, `$1`…`$9`, and the `model:` and `mode:` a command asks for; instructions from `CLAUDE.local.md`, `GEMINI.md` and `.github/copilot-instructions.md`, and the files a `CLAUDE.md` pulls in with `@path`.
- **An ignore file for the agent.** `.vyotiqignore`, `.aiignore` or `.cursorignore` at the workspace root lists paths the agent's tools may not read, edit or find, in the shape of a `.gitignore`. The agent can't change them.
- **Math in replies.** `$$…$$`, `$$` blocks, ```` ```math ```` and the `\(…\)` other models write are typeset. A single `$` stays text, so prices and `$HOME` read as written.
- **Earlier briefs.** `↑` in an empty New task brief brings back the last one you started, across tasks and workspaces, and `↓` goes the other way.
- **Six more @-mentions**: terminal output, the uncommitted diff, a commit, a URL, a pull request or issue, and a code symbol.
- **In the record.** A command card can copy the command or its output, or run it again in your terminal, and Find searches command output too. Alt+← and Alt+→ move back and forward through views and tasks. Fork from here starts a new task from any instruction.
- **Recently deleted.** A deleted task waits 30 days and can be restored. The navigator row also gains Open beside, Mark unread and Reveal worktree folder.
- **Checks, issues and conversation in the Pull request tab.** A failed GitHub Actions check shows the failing step's log, can be re-run, and Hand to the agent carries the log. Issues open in the app with Start a task, and a brief that says "Fixes #N" carries it into the drafted pull request. The tab shows the conversation, takes a comment, and edits the description, with a preview. It requests and withdraws reviewers, turns on Merge when ready where the repository allows it, leaves a merge queue, and lists every comment rather than the latest 50. A merged branch offers Clean up.
- **More git in Changes.** Discard your own changes, with a copy kept in the OS trash and an undo. Stage or unstage one hunk, amend the last unpushed commit, and switch branches with your changes stashed on the branch they belong to. Manage branches and stashes, revert or branch from a commit, and pull with rebase. Changes fetches every few minutes while it's open, so ahead and behind stay true, and lists every changed file past the first 200 on request.
- **Batched review comments.** Comments on lines and line ranges, across files, collect into one instruction you send when you're done.
- **A fuller terminal.** Find, Clear, Copy all and Rename on each tab. Each tab can take its own shell, WSL included, and Settings takes a shell program path. Ask the agent sends a selection to the task. Draw with the GPU renders heavy output faster.
- **Extensions keep up.** Packages installed from npm, git or a registry check for updates, and Discover searches the official MCP Registry beside the bundled catalog. The catalog gains four servers. Packages that repeat a built-in tool say "built in already". Workspace rules can be switched off. Agent-built tools can be viewed and deleted in the app. Hooks have a page in Settings, with the files they come from, their trust, and a log of their runs.
- **Setup meets you where you are.** It notices keys in your environment and local servers that are running, and takes a key in place. Common OpenAI-compatible hosts are presets, so nobody needs a base URL. The proxy takes a user name and password. Vertex AI runs its open models too.
- **A sandbox on Windows.** Settings, Tools, Sandbox: on Windows, Workspace only runs the agent's commands at low integrity, so they can write the workspace and temp folders and little else. It cannot block reads or the network, and bash cannot start under it, so commands run in PowerShell or cmd.
- **Arm builds.** Windows ships x64 and arm64 installers, Linux ships arm64, and the Download page lists both.
- **A beta channel**, for updates before they reach everyone.
- **Local dictation in other languages**, with a multilingual model to download.
- **Sound and quiet hours** for notifications.
- **Instances survive a restart.** When an interrupted task resumes, its interrupted instances get their checkout back from their kept branch and carry on, and the task is told which came back.

## Improved

- **Very long tasks stay quick to open in full.** A run's work shows its latest 200 rows, with "Show 200 more" above them for the rest. On a 5,000-call task with every page loaded, unfolding the work went from 11 seconds to under one, and typing stays responsive while it is open. Find still reaches the earlier rows.
- **Handing work to another agent is now a judgment call.** The agent starts a sub-agent when your request splits into two or more independent pieces that can run in parallel, or when one piece is large enough that an agent given a narrow brief would finish it faster. A single small, tightly coupled edit, a straight answer and a read-only lookup are done in the main task, because doing them there is quicker and clearer, and nothing is spawned just to look thorough.
- **Steps that depend on each other stay together.** When the agent does hand work over, it never splits steps that need one another. Each delegated step still goes to its own agent with a complete brief: what to deliver, what is in scope, how it will be checked and which parts of your workspace it touches. A child never has to guess at a conversation it cannot see.
- **A plan is published only when the work touches your workspace.** Work that changes files, runs commands or otherwise acts on your project gets a plan, with each step carrying a check you can watch run. A direct answer or a read-only lookup gets none.
- **Fewer wasted turns.** A run that had not published a plan is no longer asked where its plan is, which cost two extra model round trips on an ordinary request. A run whose checks are all met is not sent back to decorate a finished plan.
- **Smaller prompts.** A step no longer carries tools that cannot work in the workspace: the MCP server tools with no server enabled, the GitHub tools with no remote, and the notebook editor with no notebook. Process advice names only your operating system's commands, and a task with no Done-when no longer carries a boilerplate one.
- **Approvals start at Edits and commands**, the choice Setup recommends, for new installs and for anyone who never chose. "Unattended" no longer names two things: Setup's choice is Nothing, as in Settings, and the switch is Approve low-risk tools on their own. When the agent asks a question is a setting of its own.
- **Commit drafts follow the repository.** Conventional Commits only where the history uses them, and "Fix x" becomes "fix: x", not "fix: Fix x".
- **Checks count.** Running a test file directly, `node test.js` or `python test_x.py`, counts as a check for the receipt and the verification gate.
- **Setup starts on the key form** when no local server answers, with OpenCode Go first in the list.
- **The inspector fits a narrow window.** Tabs that don't fit move into a menu at the end of the strip, marked when one of them has something waiting, instead of scrolling out of sight.
- **Smaller things.** The slash menu lists ready commands before skills to install. The command palette offers task commands only in a task. Commit opens its box directly when there is nothing else to choose. The Pull request tab asks before it creates a GitHub repository. A closed folder in Files marks that it holds a changed file. The index counts "source files". Usage shows "—" when nothing was priced, not "$0". Home shows the home workspace as not a repository, not as an error.

## Fixed

- **`/help` and `/loop` mistakes stay local.** They used to be sent to the model as your instruction, which started a paid run to print a list.
- **Closing the window no longer stops your tasks without asking.** See Keep running in the tray.
- **Files, Delete moves to the OS trash** instead of deleting for good.
- **The Pull request tab no longer offers a pull request** for a task that changed nothing.
- **Commit is no longer the primary button** while this task has changed nothing.
- **Closing Extensions returns to where you were**, as Settings does.
- **Opening the app during a headless run** no longer marks that run interrupted.
- **New task's "What the agent will see"** lines up with the brief.
- **Both Delete dialogs say the same thing**, that the task goes to Recently deleted for 30 days, and warn when helper-instance branches will be lost for good.
- **Offline follow-up previews** no longer replace every letter "s" with a space.

## Security

- **GitHub sign-in no longer asks for the `gist` scope**, which nothing used.
- **The Windows sandbox labels come off** when you remove the workspace or uninstall Agent V, not only when you turn the sandbox off.
