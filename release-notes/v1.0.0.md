Agent V 1.0.0 is the rebuilt app. The chat window is gone: you give the agent a task, and the app keeps a record of the work — each step it took, what it changed, the checks it was held to and whether they held — beside the files, terminal, browser and pull request it worked in. Tasks are sorted by what they need from you, not by when they were opened, so the question "what is waiting on me?" is answered before you look for it.

## Added

- **Tasks, sorted by what they need.** The navigator groups every task in your open workspaces as Needs you, Running, Ready for review, Pinned and Earlier, with finished work split into Today, Yesterday, This week and Older, and Drafts kept apart. Home, Inbox, Extensions, Usage and Settings sit at its foot. Needs you means a tool call or a question is waiting on you right now; Ready for review means the agent finished and left edits you have not kept or undone. Ctrl J jumps to the next task that needs you.
- **A record of the work, not a chat transcript.** A task reads as the instruction you gave, then the steps the agent took in order — each file it read or wrote, each command and its result, its plan and its progress through it — with terminal and diff output kept in bordered blocks so they stay easy to read. Find (Ctrl F) searches the record.
- **Done-when checks.** A new task can carry the conditions that mean it is finished. The agent sees them, may add its own while planning, and before it stops must mark each one met or not met with the evidence — a command and its result, or a file and line. The record and the run's receipt show every check and its verdict.
- **The inspector.** Changes, Files, Terminal, Browser, Pull request and Plan sit in one strip beside the task (Ctrl I to show or hide, Alt 1 to Alt 6 for each tab, Ctrl Shift I to expand). Changes counts what this task wrote from its own checkpoints, exactly or not at all, and the expanded view is a review: mark files viewed, keep or undo each, and ask about any line.
- **A New task page.** Write the brief, list its done-when checks, choose Ask or Agent and see what the agent will be told about the workspace before it starts. Ctrl Enter starts it. A brief can be saved as a draft and picked up later from Drafts.
- **Start a task in a new worktree.** A task can run on its own branch in its own folder, so your checkout is untouched while it works. When it is done, merge it back into the branch it came from or discard it; a merge that conflicts is stopped and names the files.
- **Rewind, and Redo.** Rewinding to an earlier instruction removes the later steps from the record and takes each file back as far as it safely can. The dialog says ahead of time which files go back, which stop partway and why — a change you made since, or a write that kept no copy — and the rewind does exactly that. A rewind is kept, so Redo brings it back until you send a new instruction or change those files.
- **Home and Usage.** Home is where work starts: a field to begin a task, what needs you across every workspace, and the week so far. Usage shows tasks, tokens and spend over the days you choose, for one workspace or all of them, with the model mix, the tools that failed, the edits no check followed, and the share of input served from the provider's cache wherever that was measured.
- **Instructions while it works.** Anything you type while a task runs is queued for when its turn ends. Shift Enter sends it at once: the agent's current reply is cut short and your instruction is the next thing it reads.
- **Always allow a command, not the terminal.** Allowing a terminal command for a workspace now allows that command — `pnpm test`, say — rather than every command the agent might run. A command chained with another, piped or redirected never matches an allowed one.
- **Instances at once.** Settings caps how many helper instances a task may run in parallel, up to sixteen.
- **Pause indexing.** A workspace's code index can be paused and resumed from Settings; paused, it stays paused through edits, and the agent is told the index is paused rather than that it is missing.
- **A commit message ready when you open Changes.** The message is written once per set of changes and kept, so reopening Changes does not ask the model again.
- **Search and commands.** Ctrl K finds tasks, files and commands in one list, and Settings rows too. File search reads a list kept per workspace, refreshed when files change, rather than walking the folder on every keystroke.
- **Notifications, an inbox and What's new.** A finished task says how many files wait for review and how many checks were met; a waiting approval says what the agent wants to run. The inbox keeps them, and an update that is ready waits there instead of interrupting you.
- **Set up on first run.** The first launch checks your provider key against the provider, asks how much the agent may do without asking, and opens the folder you choose.
- **The agent can write itself a tool.** When a run keeps repeating a mechanical shape no built-in tool covers, it can write one as a small module that joins its catalog. Calling one asks you first, every time the file behind it has changed, and the approval shows the code.
- **Twenty-six engineering skills in Extensions.** Matt Pocock's Skills for Real Engineers, vendored under his name and MIT licence. Installing one that calls others installs those too, and says which.
- **The agent can see screenshots.** It can snip a window, a region or a whole display, read an image file in your project, and see the images an MCP server returns. A screen snip asks you first every time, even with approvals off. Only the three most recent images stay in its context.
- **Your own endpoints.** Settings, Providers, Custom endpoints adds any OpenAI-compatible server by name and base URL, up to twenty, each with its own key and its own tab in the model picker. Removing the endpoint a task uses stops that task from starting rather than sending it somewhere else.
- **Voice input writes as you speak.** A quick draft model shows words while you talk and the model you chose replaces them at each pause. Moonshine Base is a new local model that turns a phrase into text in well under a second, against three or four seconds for Whisper Small. Live words from OpenAI are there too, off by default: they use your OpenAI key and OpenAI bills them by the minute.
- **Design level-up in Extensions,** installed by default: twenty-five techniques for making what the agent designs look finished, from real fonts and a design system to motion.
- **An empty folder offers to start a repository.** Nothing runs git init for you; it is a button, and it refuses inside an existing repository.

## Improved

- **Two modes, Ask and Agent.** Plan mode is folded into Agent: the agent publishes its plan with its checks and carries on to implement it in the same task. A task saved in Plan mode opens in Agent.
- **Settings in three groups.** App, Agent and System, with every value you changed from its default marked and a way back to the default beside it.
- **Extensions in one list.** Skills, MCP servers, plugins and rules share one list, and each item says what it still needs before it works.
- **Compaction and commit-message spend is counted.** Both are billed calls with no turn behind them; they are recorded against the task and the day they happened on.
- **A conversation the provider has lost no longer ends the task.** When a provider's stored turn has expired, the step resends the full history once and carries on.
- **A rebuild does not take a running window down.** Old parts of the interface are kept until nothing can still be using them, and a window caught mid-load is reloaded by the app.
- **One row of controls under every instruction field.** Agent or Ask, the model and its effort, the context meter, attach and dictate, then a visible Send button, which reads Queue while the task runs. The New task page and Edit and rerun use the same row.
- **The record reads in the order it happened.** Your instruction, then the work, then the result. The result used to jump to the top when a run ended, above the instruction it answered. A finished run with an answer folds its setup work to one line you can open.
- **Allow for this task means the whole task.** It used to cover one run, so the next instruction you gave asked again. Other tasks still ask.
- **Instructions sent offline wait in the queue** as Queued, offline, where you can edit or remove them before they go.
- **Helper instance branches are cleaned up.** A finished helper's branch is deleted once its commits are in another branch, and an unmerged one once its last commit is fourteen days old. Nothing ever removed them before: one repository had collected 133.
- **Slow-starting MCP servers get two minutes to answer,** not one. A server launched through npx on a cold cache used to be reported as not responding while it was still downloading.
- **Electron 44.** The app runs on Chromium 152 and Node 24.

## Removed

- **Teammates.** Agent profiles, delegated tasks, the task scheduler, teammate memory and the Teammates view are gone, with their tools and the create-teammate skill. Helper instances inside a task remain.
- **The chat sidebar and side rail.** The navigator and the inspector replace them.
- **The Density setting.** It only sized controls the redesign no longer draws.

## Fixed

- **The window no longer stops responding at launch.** Reopening a task whose run had deleted a large folder re-read every file it touched, which took minutes on a cold disk, and the code index saved its database on the same thread as the window. Both now run in the background.
- **A space typed in the instruction field could press Allow.** The approval card took focus back every time the page redrew, so the next key you typed answered it.
- **Saving in Files could fail with "Recovery session is stale"** when the panel opened while the app was still preparing it.
- **A model that streamed thousands of tool calls at once no longer ends the task.** One run repeated the same command 5,862 times in a single reply and never recovered. A reply with more than 64 calls is now cut off before any of them runs, and the agent is told why.
- **A rewind that cannot write one file changes nothing.** A file locked by another program, a read-only file or a full disk used to leave the files before it rewound and the record as it was. Every file is put back and the message names the file and why.
- **A file two rewound runs changed is counted once.** The dialog and the result both list each file once, by where the rewind leaves it.
- **A rewind no longer writes over a change you made.** When a newer run's write is stopped by your edit, older runs leave the file alone too; before, a run that had crashed before saving its checkpoint could restore its copy over your change.
- **Undo could delete files the agent never touched,** when a workspace held more files than one scan records. Only what is on disk now decides what the agent created.

## Security

- **Applying a patch is approval-gated like any other write,** and a tool the agent wrote for itself stays gated even with approvals off.
- **Your file paths and file contents stay out of the log.** Paths relative to your project and the file text quoted in failed searches and edits used to be written out whole.
- **colord is updated past GHSA-2wm5-q62r-hmrv.**
- **lodash-es is updated past GHSA-r5fr-rjxr-66jc,** which reached the app through the diagram renderer.

## Known issues

- Windows and macOS builds are unsigned. Windows SmartScreen warns on first run, and macOS Gatekeeper refuses a double-click — open it from the right-click menu once.
- Crash reports are not sent from this build. Crashes are recorded on your own machine only.
