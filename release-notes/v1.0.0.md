The first stable release of Agent V, and where its version history starts. It is a security release as much as a feature one: several places where a credential or a local command could cross a boundary it had no business crossing are now closed. Connected MCP servers also stopped charging every run for tools it never touches, and the chat window finally shows you where a run is working while it works.

## Added

- **Every request the browser makes now goes through one egress policy.** The domain allowlist was previously enforced on navigation only, so a page served from an allowed host could fetch, post a form, or open a socket to any host in the world. Scripts, images, background requests and WebSockets are now judged by the same rule as the address bar, and a page can no longer reach past the list you set.
- **Each run keeps a durable record of where it went.** Every request the run made, allowed or refused, is written to that run's own record rather than to a log that scrolls away. Nothing can be enforced without also being written down, so what a run touched stays answerable after it finishes.
- **The agent is told when the gate refused a page's requests.** A refusal used to be invisible to it: the page loaded, its background requests were cancelled, and what the run saw was a site that merely looked broken — so it would retry, or report the site as down, while the one fact that explained it sat in a record nothing read. It is now told, and can say so instead of guessing.
- **The Terminal panel shows the run's own shell as it happens.** Commands the agent runs, their output and their exit codes appear in a read-only session beside your own shells, live rather than after the fact. The commands themselves still run exactly as before — the panel receives a copy of the same bytes, so nothing about what the model reads has changed.
- **A rail down the side of the chat says where the run is working.** Files pulses with the file being written and names it, Terminal pulses with the command running, and Changes carries a count of edits waiting for you to look at them. Only work still in flight is marked, so a marker means something is happening now. The strip is a single tab stop that the arrow keys walk.
- **The Files panel can follow the agent.** With follow on, the panel opens whatever file the run is currently writing. It follows writes and ignores reads — following reads would drag the editor across a dozen files in one turn — and it picks the path out of an edit that is still arriving, which is exactly when watching is useful.
- **File names on tool cards open the file, at the line that changed.** An edit's first changed line is read from the diff itself rather than guessed, so the editor lands where the change is. A path that does not resolve inside the open workspace is shown plainly instead of as a link that fails when clicked.
- **The pull request panel keeps up with CI by itself.** While checks are still running it re-asks GitHub and updates in place; it stops once every check has settled, and does not poll a merged or closed pull request, or tick at all while the window is hidden.

## Improved

- **Connected MCP servers no longer charge you for tools a run never touches.** Every connected tool's schema used to be sent on every single step — measured at 67,020 tokens across 95 tools on a four-server install, one server alone accounting for 54,595, re-sent whether or not the run went near MCP. A step now lists the connected servers by name and nothing more; the agent loads a server when it needs one, and calling a tool loads it too, so asking costs no extra round trip. Marketplace has a per-server override for a server you want ready with no wait, and Settings keeps a switch that restores the previous behaviour wholesale.
- **The context meter prices each server you have not loaded.** Deferred tools are now broken down per server, so the meter says what loading each one would actually cost before you decide to.
- **The sidebar asks whether a run is still going, rather than trusting a stored snapshot.** A run's recorded state can say it is working long after it stopped, which left chats spinning forever. The indicator now reconciles against the live list of active runs, and stops when that list says the run has finished.

## Removed

- **The 0.x preview releases.** Versions 0.1.0 through 0.3.0 were development previews and have been withdrawn along with their tags and download links; 1.0.0 is the first release of this codebase. If you are running a preview, this release reaches you as a normal update and nothing on your machine needs changing. Older download links no longer resolve — take this version instead.

## Fixed

- **Live terminal output could go dark for the rest of a step.** The queue feeding output to the window kept counting bytes it had already released, so its running total only ever climbed. Once that total passed the cap, every new chunk was dropped the moment it arrived — one run produced 43,934 dropped-chunk warnings in 58 seconds on a queue that was empty at the time. The output was never lost from the record, but you stopped seeing it happen.
- **Undo could restore part of a directory and report it finished.** When a directory held more files than a checkpoint will record, the directory itself was marked unrestorable while the files already recorded stayed individually undoable — so Undo put back a fraction of the tree and reported a completed undo, leaving a directory quietly missing most of its contents. A tree that cannot be restored whole is no longer treated as restorable at all.
- **One turn's undo history could be filed under the previous turn.** If a new turn began before the previous one had finished closing out, its records landed under the earlier turn's heading, which also made the earlier turn report this turn's files as its own. Each turn is now closed under its own heading and stays separately undoable.
- **Closing the window with the X button now saves your editor state.** On Windows and Linux the window was torn down before anything could ask the editor to save, and the quit that followed reported a clean save that had never been asked for. The app now asks while the window is still there to answer.
- **Choosing Wait while quitting quit anyway.** The editor flush gives up after four and a half seconds, just ahead of the five-second dialog — and because giving up that way was not a failure, Wait found an already-settled result and quit on the spot. Wait now reissues the flush and actually waits, while the hard limit that stops a run holding the app open forever still applies.
- **A queued follow-up message could be carried out twice.** When the file holding queued messages could not be deleted — on Windows routinely just an antivirus or search indexer holding it open — the message stayed on disk and was read back in on the next turn, so the agent followed the same instruction a second time.
- **A deleted chat could come back as an empty row.** A status write already in flight when the chat was deleted recreated the folder it was writing into, leaving behind a chat with nothing in it. Writes now check again on the way to disk and abandon a run that has been deleted.
- **The hover actions on a sidebar row could not be clicked.** Two conflicting rules were applied to the same strip and the one that disables clicks always won, so the buttons appeared on hover and then ignored you. This also fixes the confirm step when closing a workspace, which sat behind the same dead strip.
- **Every chat message looked like it was rebinding its teammate.** A message that says nothing about the teammate is supposed to inherit the run's existing binding, but because the field was always present — carrying no value — every send read as an explicit statement, and that inheritance never applied to chat at all.
- **Events written during the final flush at quit could be lost.** Work queued while the flush was already waiting chained onto a second promise the flush never saw, so it could finish and report success with writes still outstanding. Those last writes are exactly the ones worth keeping.

## Security

- **Chat requests no longer follow a redirect to another host.** Provider credentials travel as an API key header as well as an authorization header, and the platform only strips the latter when a redirect crosses origins — so a redirect on this path could have handed an API key to a different host entirely. This is the main chat path, and it was the only network path in the app with no redirect discipline at all. Same-origin redirects are followed; anything else is refused outright.
- **Fetching a web page drops your credentials when a redirect crosses origins.** That path follows redirects itself rather than leaving it to the platform, so the platform's protection did not apply to it either. Authorization, cookie and API key headers are now stripped the moment a hop leaves the origin they were meant for.
- **A custom stylesheet has to be one you picked in the file dialog.** The app reads whatever file that setting names and hands the contents to the window, so a setting that could be written freely was a way to read almost any file on your machine — private keys, environment files, anything up to a quarter of a megabyte. Only a file you chose yourself is honoured, and a stylesheet you had already saved still survives a restart.
- **Running a local MCP command now asks first, and names the command.** Agreeing once to the risk of marketplace servers used to stand in for consent to every later launch. Any command line the app has not run before is shown in full and waits for you to agree, because this runs on your machine as you.
- **A request for a provider's model list cannot redirect your API key.** That request sends the stored key to whatever address it is given, and the address was only checked for the two providers whose address is meant to be configurable. Every other provider now refuses a supplied address rather than sending your key somewhere it was never meant to go.

## Known issues

- Windows and macOS builds are unsigned. Windows SmartScreen warns on first run, and macOS Gatekeeper refuses a double-click — open it from the right-click menu once to get past that.
- Crash reports are not sent from this build. Crashes are still recorded on your own machine, but the reporting key was absent when it was packaged, so nothing is transmitted anywhere.
